# Документация по визуализации технологического процесса

## Обзор

Система визуализации технологического процесса предназначена для отображения состояния устройств на странице EPLAN. Она была портирована с C# (из проекта EasyEPLANner) на C++.

## Основные компоненты

### 1. DrawInfo (src/editor/draw_info.h)

Класс `DrawInfo` отвечает за настройку визуального отображения устройств.

#### Стили отрисовки (Style enum)

- **NO_DRAW** - Устройство не отображается
- **GRAY_BOX** - Серая рамка (обычное состояние)
- **GREEN_BOX** - Зеленая рамка (активное устройство)
- **GREEN_UPPER_BOX** - Зеленая верхняя рамка
- **GREEN_LOWER_BOX** - Зеленая нижняя рамка
- **GREEN_GRAY_BOX** - Зелено-серая рамка (смешанное состояние)
- **RED_BOX** - Красная рамка (ошибка/конфликт)

#### Типы действий (ActionType enum)

Типы действий используют битовые флаги для проверки совместимости:

- **OTHER** (0b1111) - Общее действие, совместимо со всеми
- **ON_DEVICE** (0b0001) - Включение устройства
- **OFF_DEVICE** (0b0010) - Выключение устройства
- **DELAYED_ON_DEVICE** (0b0110) - Отложенное включение
- **DELAYED_OFF_DEVICE** (0b0101) - Отложенное выключение

#### Логика проверки конфликтов

При применении побитового И к типам действий:
- Если результат = 0, действия конфликтуют (отображается RED_BOX)
- Если результат ≠ 0, действия совместимы

Примеры конфликтов:
```
ON_DEVICE (0b0001) & OFF_DEVICE (0b0010) = 0b0000 (конфликт!)
ON_DEVICE (0b0001) & DELAYED_ON_DEVICE (0b0110) = 0b0000 (конфликт!)
OFF_DEVICE (0b0010) & DELAYED_OFF_DEVICE (0b0101) = 0b0000 (конфликт!)
```

Примеры совместимости:
```
OTHER (0b1111) & ON_DEVICE (0b0001) = 0b0001 (совместимы)
DELAYED_ON_DEVICE (0b0110) & DELAYED_OFF_DEVICE (0b0101) = 0b0100 (совместимы)
```

#### Методы фильтрации

**Filter()** - Базовая фильтрация по устройствам:
1. Группирует устройства по имени
2. Для каждой группы применяет правила:
   - Если есть RED_BOX - приоритет красной рамке
   - Если разные стили (кроме NO_DRAW) - GREEN_GRAY_BOX
   - Иначе - первый стиль из группы

**FilterByActions()** - Фильтрация с проверкой конфликтов действий:
1. Группирует устройства по имени
2. Проверяет битовое И всех действий в группе
3. Для каждой группы применяет правила:
   - Если побитовое И = 0 - RED_BOX (конфликт действий)
   - Если разные стили - GREEN_GRAY_BOX
   - Иначе - первый стиль из группы

### 2. TreeViewItem (src/editor/tree_view_item.h)

Базовый класс для элементов иерархической структуры технологических объектов.

#### Основные методы

- `IsDrawOnEplanPage()` - Проверка необходимости отображения
- `GetObjectToDrawOnEplanPage()` - Получение списка DrawInfo для отрисовки
- `GetDisplayText()` - Получение текста для отображения в UI
- `IsEditable()` - Проверка возможности редактирования

### 3. Action (src/techobject/action.h)

Класс действия над устройствами (включение, выключение и т.д.).

#### Функциональность

- Управление списком устройств
- Настройка стиля отрисовки
- Установка типа действия
- Генерация DrawInfo для визуализации

#### Пример использования

```cpp
// Создание действия
auto action = std::make_unique<Action>("Открыть клапан", "open_valve");

// Настройка визуализации
action->SetDrawStyle(DrawInfo::Style::GREEN_BOX);
action->SetActionType(DrawInfo::ActionType::ON_DEVICE);

// Добавление устройств
auto valve = std::make_shared<MockDevice>("V101");
action->AddDevice(valve);

// Получение информации для отрисовки
if (action->IsDrawOnEplanPage()) {
    auto drawInfos = action->GetObjectToDrawOnEplanPage();
    // Используем drawInfos для визуализации
}
```

## Отличия от C# версии

1. **Умные указатели** - Использование `std::shared_ptr` вместо сборщика мусора
2. **STL контейнеры** - `std::vector`, `std::unordered_map` вместо List и Dictionary
3. **Явное управление памятью** - Деструкторы и правило пяти (Rule of Five)
4. **Строгая типизация enum** - `enum class` вместо обычных enum
5. **Константность** - Использование `const` методов для read-only операций
